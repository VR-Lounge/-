# 🚀 Деплой бота на Render (бесплатно)

## ✅ Преимущества Render:

- **Бесплатный tier** с автодеплоем из GitHub
- Автоматический перезапуск при падении
- HTTPS из коробки
- Логи в реальном времени
- Автодеплой при пуше в GitHub

## 📋 Пошаговая инструкция:

### Шаг 1: Подготовка репозитория

1. Убедитесь, что все изменения закоммичены:
   ```bash
   git status
   git add .
   git commit -m "Миграция на Render, обновлен токен бота"
   git push origin main
   ```

### Шаг 2: Создание аккаунта на Render

1. Откройте: https://render.com
2. Нажмите **"Get Started for Free"**
3. Войдите через **GitHub** (рекомендуется)
4. Подтвердите доступ к вашему репозиторию

### Шаг 3: Создание Web Service

1. В Dashboard нажмите **"New +"** → **"Web Service"**
2. Выберите репозиторий: `VR-Lounge/-` (ваш репозиторий)
3. Настройки:
   - **Name:** `vr-lounge-telegram-bot`
   - **Environment:** `Node`
   - **Region:** `Frankfurt` (ближе к России) или любой другой
   - **Branch:** `main`
   - **Root Directory:** (оставьте пустым)
   - **Build Command:** `npm install`
   - **Start Command:** `node telegram-bot.js`
   - **Plan:** `Free` (бесплатный)

4. Нажмите **"Advanced"** и добавьте переменные окружения:

### Шаг 4: Настройка переменных окружения

В разделе **"Environment Variables"** добавьте:

| Ключ | Значение | Описание |
|------|----------|----------|
| `TELEGRAM_BOT_TOKEN` | `YOUR_TELEGRAM_BOT_TOKEN` | Токен нового бота |
| `ADMIN_GROUP_ID` | `-1002640127163` | ID группы администраторов |
| `CLIENT_MINI_APP_URL` | `https://vr-lounge.github.io/-/client-booking-miniapp.html` | URL Mini App для клиентов |
| `MINI_APP_URL` | `https://vr-lounge.github.io/-/telegram-miniapp.html` | URL Mini App для админов |
| `FIREBASE_SERVICE_ACCOUNT` | `[весь JSON как одну строку]` | Ключ Firebase |

**Для `FIREBASE_SERVICE_ACCOUNT`:**
1. Откройте файл `firebase-service-account.json`
2. Скопируйте весь JSON
3. В Render вставьте весь JSON как одну строку (без переносов)
4. Или оставьте пустым, если используете файл (но лучше переменная)

### Шаг 5: Настройка Firebase Service Account

**Вариант А: Через переменную окружения (рекомендуется)**

1. Откройте `firebase-service-account.json`
2. Скопируйте весь JSON
3. В Render вставьте в переменную `FIREBASE_SERVICE_ACCOUNT` как одну строку

**Вариант Б: Через файл**

Если оставляете файл в репозитории:
- Убедитесь, что файл `firebase-service-account.json` закоммичен
- В Render переменную `FIREBASE_SERVICE_ACCOUNT` оставьте пустой

⚠️ **Рекомендуется Вариант А** - безопаснее, так как файл не будет в репозитории.

### Шаг 6: Деплой

1. Нажмите **"Create Web Service"**
2. Render начнет деплой (займет 2-3 минуты)
3. Следите за логами в реальном времени

### Шаг 7: Проверка работы

После деплоя:

1. **Проверьте логи:**
   - В Render Dashboard → ваш сервис → вкладка "Logs"
   - Должны быть строки:
     ```
     ✅ Telegram бот инициализирован с polling: true
     🤖 Telegram бот запущен!
     ✅ Бот готов к работе!
     ```

2. **Протестируйте бота:**
   - Откройте Telegram
   - Найдите `@vr_lounge33_bot`
   - Отправьте `/start`
   - Бот должен ответить

3. **Проверьте уведомления:**
   - Создайте тестовую запись через Mini App
   - Проверьте, приходит ли уведомление в админ-группу

## 🔄 Автоматический деплой

После первой настройки:
- Каждый push в `main` ветку → автоматический деплой
- Render автоматически перезапускает бота с новым кодом

## ⚙️ Настройки Render Free Tier

### Ограничения:
- **Может засыпать** после 15 минут неактивности
- При первом запросе просыпается (задержка ~30 секунд)
- Для бота с polling это нормально - он будет работать постоянно

### Если бот засыпает:
- Это нормально для бесплатного tier
- При получении обновления от Telegram бот просыпается
- Polling продолжает работать

## 🔧 Настройка здоровья (Health Check)

Render может проверять здоровье сервиса. Для бота это не критично, но можно настроить:

1. В настройках сервиса → "Health Check Path"
2. Можно оставить пустым (бот работает через polling, не HTTP)

- Логи в реальном времени
- История логов (бесплатно)

### Метрики:

## 🔐 Безопасность

### Важно:

- ✅ Логи не содержат чувствительных данных

1. **Засыпание сервиса:**

   - 0.5 vCPU (для бота достаточно)

3. **Резервное копирование:**
   - Все данные в Firebase (автоматически)
   - Код в GitHub (автоматически)
   - Настройки в Render Dashboard (сохраняются)

## 🚨 Если что-то не работает

### Проблема: Бот не отвечает

**Решение:**
1. Проверьте логи в Render
2. Убедитесь, что токен правильный
3. Проверьте переменные окружения

### Проблема: Ошибка "Unauthorized"

**Решение:**
1. Проверьте токен в переменных окружения
2. Убедитесь, что токен от правильного бота (`vr_lounge33_bot`)

### Проблема: Бот засыпает

**Решение:**
- Это нормально для бесплатного tier
- Бот просыпается при получении обновлений
- Для более стабильной работы можно использовать платный tier ($7/мес)

## ✅ После миграции

1. Удалите старый сервис в Railway (чтобы избежать конфликтов)
2. Обновите ссылки на бота (если username изменился)
3. Проверьте работу всех функций
